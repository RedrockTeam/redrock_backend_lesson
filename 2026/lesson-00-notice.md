# 第零节课

## 如何正确的查找攻略

 在往年的时候这一章节更多聚焦于提供权威的信息渠道，以及如何一步一步分析解决问题，定位 bug 并修复验证。但是这样一步一步寻找攻略定位问题的方式并不成为目前的主流，把问题丢给 ai 更省心，也更快速，因此，在重新叙述 old method 之前我们更应该在这里讨论，在初学 go 语言的阶段，ai 应该扮演一个什么样的角色。

多人可能会有这种的疑惑，既然 ai 已经这么强了，那么我们为什么需要学这个，未来真的还需要程序员吗，既然 ai 已经这么强了，为什么我们还需要想这样一步一步学习一步一步试错纠正，亲手书写代码

对于第一个问题，我自己也在寻找答案，ai 的出现完全撕碎了传统软件行业的边界，重塑了整个互联网生态，仅仅是在 gpt2 以来的八年时间，我们尚且不知道 ai 到底会发展到哪种地步，以及未来留给人做的部分到底还剩多少。在这个课程做的尝试是，不再将这整个课程视作一个 go 语言初级工程师的培养方案，期待学完之后刷刷算法刷刷八股就去投简历刷实习进大厂--在过往红岩网校超过十年中每一年都得到多次验证的道路，而是将这次课程（至少是在大一上的部分）作为一个进入计算机世界的抓手，目前近乎不存在传统意义上的后端岗位，无论是 web3 还是 agent的岗位方向在当下也没有沉淀出一条阶梯式对接就业的学习链路，因此我更希望的是通过半年的时间通过这套课程来让初学者具备基础的工程能力和架构思想，也同时回顾并梳理我过去一年学习的内容。我不是很清楚 ai 的出现让人们应该放弃什么，但是面对问题独立思考并将思考落地成工程结果的能力我想是不应该放弃的。

对于第二个问题，可以这么说，ai 可以代替你完成很多工作，但无法代替你完成成长，这个课程被设计成需要你自己去动手自己去书写的学习路径，无论是非强制性的练习题还是强制性的项目搭建，而这些关卡的设计并不是为了让你完成，而是让你在试错和查阅资料询问他人的过程中培养起来真正的能力，这个过程并不轻松，甚至会让人怀疑自己是否适合做这个，但正是在这个痛苦的过程中，你才开始建立工程师的核心能力：面对复杂系统一步一步定位问题并进行解决，根据需求自己搭建网络选择技术框架并交付结果

当然，我们并不是禁止你使用 ai，相反 ai 可以很好的成为你的伙伴，比如你可以让ai 帮你：
- 解释一个你刚接触的概念，并要求它用更基础的例子说明。
- 帮助诊断你对于报错的理解是否正确。
- 帮你检查自己的理解中是否有漏洞。
- 把你已经解决的问题整理成笔记、FAQ 或复盘。
- 模拟助教，追问你“为什么这样判断”“你打算如何验证”。

 因此，对于 ai 的应用在整个课程中我们约定以下准则
- 先自己尝试，再请 AI 帮忙：遇到问题时，不一定要独自耗很久，但也不要一开始就把问题完全交出去。自己先跑一遍读一遍，跑一次实验，记录现象，提出一个初步猜测，再尝试，实在解决不了，再问 AI：我的理解哪里可能有问题？我下一步应该优先验证什么？
- 先说出自己的判断，再让 AI 帮你检查：调试时，可以先自己尝试，并把你的现象、判断和已经排除的可能告诉 AI，再让 AI 给你排查路径、可能原因、验证方法。比如你可以这样问：我现在观察到的现象是……我的预期是……我已经尝试了XXX，但是没有解决，我觉得XXX不行，是因为YYY……
- 对结论做充分验证：AI 的回答可能很流畅，但流畅不等于正确。当 AI 告诉你“问题可能在这里”时，你可以继续问：为什么？有什么证据？我应该看哪段代码、哪个日志来确认？
- 把 AI 的帮助变成自己的沉淀：一次好的 AI 对话，不应该只停留在聊天窗口里。你可以把其中真正有价值的部分整理成自己的笔记：这个问题是什么，现象是什么，错误理解在哪里，最后怎么验证，下一次如何避免。当你能把一次调试经历讲清楚，它才真正成为你的经验。
- 保留亲手训练的时间：些事情值得你慢一点亲自做：亲手写一段代码，亲手跑一个测试，亲眼看一次波形，亲自解释一个现象，亲自复盘一个 bug。这些事情看起来慢，却会让你在未来使用 AI 时更快。因为你知道自己在问什么，也知道答案应该如何落地。

或者如果你希望具体一些建议的话：第一，不要使用 agent 直接完成作业或帮你补全代码，将 ai 的时候收敛到 web 界面对话上，第二，将 ai 变成你的助手例如
```text
你现在是我的go 语言学习伙伴。

我希望你帮助我学习，而不是替我完成学习任务。你的目标不是直接给我最终答案，而是帮助我更好地理解问
题、形成判断、验证结论，并逐步建立独立调试和系统性思考的能力。

请你遵守以下原则：

1. 不要一上来直接给完整代码、完整实现或最终结论。
2. 如果我的问题描述不完整，请先追问我：现象是什么、预期是什么、我已经尝试了什么、我的初步判断是什
么、我如何验证过。
3. 当我遇到 bug 或调试问题时，如果我还没有给出现象、尝试和判断，请先提醒我补充这些信息，再继续分析
    a.每种原因对应的验证方法是什么；
    b. 我应该先看哪些日志、信号、代码或文档；
    c.如何一步一步缩小问题范围。
4. 当我给出自己的判断时，请帮我检查这个判断是否合理，指出其中可能的漏洞，而不是直接替我推翻或替我判断
6. 当我明显想跳过思考、直接要答案时，请提醒我先补充自己的尝试、现象和判断。
7. 如果确实需要给出代码，请尽量先给思路、伪代码、关键片段或验证方法；只有在我明确要求并且已经理解
思路后，再给更完整的实现。
8. 每次回答最后，请尽量给我一个下一步可以亲手验证的小任务。

我接下来会把我的问题、现象、尝试和判断告诉你。请像助教一样帮我一起分析，而不是替我完成。
```

## 如何高效的提问

我们很多人可能会抗拒提问，怕问题过于简单被别人嘲笑，沉默似乎比贴上落后的标签的可能更让人舒服，怕融不进去大家，怕问题抛出来无人理会，又或者本身难以开口。

首先解决问题远比提问带来的可能风险重要的多，学长们会尽可能关注到所有消息，但是如果有疏忽，大可以直接@或者过段时间再次发送，也可以直接私聊，如果你感觉本身开口就有些困难的话，大可以以上面描述的方式去询问 ai

我们鼓励你去提问，鼓励你去将自己抽象杂乱的想法和现状去梳理成清晰的问题，很多时候在这个过程中你就能找到灵感并尝试解决，有的时候停下来重新梳理，以明确语言输出的形式，要比埋头往前冲有效的多。在 ai 时代，不同的提示词带来的效果是截然不同的，如何精准表达，如何提供有效的上下文，这些都是在我们向他们向 ai 有效提问过程中逐渐锻炼和学习的。

有效的提问是一门重要的技能，尤其是在现在的 AI 时代，无论是咨询学长还是咨询 AI，命中要害的提问往往能快速高效的解决问题！

详情可参照 [提问指南](https://lug.ustc.edu.cn/wiki/doc/howtoask/) 进行学习，下面只列出几个重点说明：

1. 拍照
**不要手机拍照！**
推荐使用  [snipaste](https://www.snipaste.com/) 截图，免费版的功能已经足够强大；如果不想下载还有 QQ 提供的截图/录屏功能可以使用，或者 win/macos 本身提供原生的截图工具，Win + Shift + S / Control + Shift + Command + 4 在 win 和 macos 中这两个快捷键组合都能让你选定区域截图并保存在剪切板中。

2. 礼貌
要有礼貌地提问，及时地回复，多用**请**和**谢谢**，学长学姐的时间同样宝贵，有礼貌的提问更能博得尊重和关注，也能让学长学姐更愿意回答你

> [!important]
> 当然，对于很多问题大家都是 0 基础，问很正常，大家不要怕，学长们都很乐意与小登打好关系，希望大家在学习过程中可以和老登们亦师亦友

3. 思考
提问前要有自己的思考，我们欢迎有思考，有深度的提问！以及，提问时请补充好相关上下文。

## 如何自学

计算机这行，重要的就是自学，这里可以负责任的告诉大家：**靠学校教的东西以后出去吃不了饭**，以后在你们求职面试中用到的技术/技能，完全需要来自己学习！网校也只是提供了一个平台，来进行指导和引领，至于最后你们能够取得什么样的成就，都要靠自己的努力


### 时间安排

如果同学们打算本科就业，就要好好规划一下大学的 3 年时间，把精力花在值得的地方，将更多的时间调用起来，根据网校就业学长的经验，非国央企不看绩点，很多厂你的简历上不写绩点都没问题，本身大学管理相对松散，总的来说，做出选择，有舍有得。不止技术，面向就业也有很多道路，面向升学也有很多道路，无论选择哪条道路都比犹豫不前虚度光阴有意义的多。


## 必备工具

### GitHub & Git

GitHub 是一个基于 Git 的代码托管平台，广泛用于软件开发和版本控制。它提供了一个协作环境，使开发者能够在全球范围内共享和管理代码。

关于GitHub 账号的注册与 Git 的使用，详见招新群群文件《Git 与 GitHub 完整指南.pdf》

### Markdown

Markdown是一门标记语言，可以广泛用于文档、博客、论坛等带格式文本内容的创作。

> [markdown 书写教程](https://www.bilibili.com/video/BV1JA411h7Gw/?vd_source=db106a91b56444cc425b52f9ebfb90bc)

推荐的编辑器：

**Typora**：
所见即所得，界面干净无干扰，左侧只有文件列表和大纲，打开就能写，不需要任何配置或插件，可以方便的查看或编辑任何位置的 md 文档。

**Obsidian**：
Obsidian 强在**知识管理能力**，可建立笔记之间的双向关联，配合**图谱视图**直观展示知识网络，适合把碎片信息逐步编织成体系化的个人知识库。

## 总结
比起现在 all in 代码，我更建议的是趁着刚进入大学这段窗口期多去认识一些人，多去尝试一些方向，进入大学迷茫是很正常的，可能看完上面这些你也只会有些犹豫和糊涂，也许你更适合去和人交流，也许你更适合去学门技术，这些不是别人能决定的，很多问题只有你自己才能给出答案。哪怕你觉得技术就业才是你的归途，但代码并不意味着生活的全部，就像后端不是计算机世界的全部，大胆尝试然后选择方向，用时间来验证你的选择。
