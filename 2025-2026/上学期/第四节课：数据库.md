# 第四节课：数据库

# 1. 数据库基础

数据库（Database）是用于长期保存数据、高并发访问数据、快速查询数据的系统，是后端的核心基础设施。

数据库作为信息系统的核心组件，承担着"数据存储、组织、管理、查询与维护"的多重职责。在现实的软件系统中，无论是教育管理系统、电商平台、金融交易系统，还是社交媒体服务，都依赖数据库持续稳定地运行。

所谓"长期保存数据"，指的是数据库具有将数据可靠写入磁盘的能力，使其能够在程序关闭、系统重启甚至服务器迁移后依旧保持完整。"高并发访问"强调数据库具备同时处理大量用户请求的能力，确保系统在访问量上升时仍能保持正常响应。"快速查询"代表数据库经过优化，可以在索引、缓存、执行计划等机制的支持下，在短时间内检索大量数据。

因此，数据库不仅是一个数据存放仓库，更是整个后端系统提供服务的基础载体，其性能、稳定性和设计质量会直接影响整个应用的可靠性。

## 1.1 数据库特性

* **持久化存储**\n指数据库能够保证数据在写入后持续存在，即使出现断电、系统重启等情况也不会丢失。其实现依赖日志、磁盘写入策略与恢复机制。
* **并发处理能力**\n现代数据库能够允许多个用户或多个程序同时访问数据，并通过锁、隔离级别、MVCC 等机制维护数据正确性，避免读写冲突。
* **高效查询**\n数据库通过索引、查询优化器、缓存机制等手段，使得对大量数据的检索依然可以在毫秒级甚至微秒级完成。
* **安全与权限控制**\n数据库能够精确控制每个用户可访问的库、表以及具体数据，有助于保障敏感信息的安全性。
* **事务一致性**\n事务通过 ACID 模型保证操作原子性、一致性、隔离性和持久性，从而避免出现数据不一致的情况，是金融、电商、库存等场景的核心保障。

## 1.2 数据库分类

数据库主要可以从"数据模型结构"和"使用场景"两个维度进行分类。在结构上，可分为关系型与非关系型。在使用上，有适合分析型查询的数据库，也有适合实时高并发访问的数据库。了解分类有助于开发者在不同业务场景下做出正确的技术选择。

### 1.2.1 关系型数据库（本课重点）

* 表结构（行、列）
* SQL 标准
* 数据一致性强
* 适合大多数业务系统
* 代表：MySQL、PostgreSQL、Oracle、SQL Server

关系型数据库基于"表格结构"组织数据，以行（记录）和列（字段）这种固定格式进行存储。由于关系型数据库遵循 SQL 标准，因此无论系统采用 MySQL、PostgreSQL 还是 Oracle，操作方式、语句结构都相对一致。

关系型数据库擅长处理结构化、高一致性要求的数据，并支持复杂查询、高度约束与关联关系，是大多数企业应用的主流选择。例如订单管理、库存查询、用户注册登录、商品信息管理等，都普遍采用关系型数据库实现。

### 1.2.2 非关系型数据库

* 无固定表结构
* 高扩展、高并发
* 代表：Redis、MongoDB、ElasticSearch

非关系型数据库（NoSQL）不使用传统表格结构，而是以键值、文档、列族、图结构等方式存储数据。这类数据库更侧重灵活性与扩展性，例如可以快速扩容到分布式架构中，适配互联网服务高流量、海量数据的特点。

它们通常用于补充关系型数据库，以实现更高性能或特定功能。

## 1.3 表设计

### 1.3.1 关系型数据库设计遵循规范化原则

* **第一范式（1NF）**\n字段不可再分（例如 don't store "1001,1002" 在一个字段中）
* **第二范式（2NF）**\n非主属性不能只依赖部分主键
* **第三范式（3NF）**\n非主属性不能依赖其他非主属性

### 1.3.2 表设计核心原则

* 字段命名规范，使用下划线命名（`user_id`、`created_at`）
* 类型选最小够用的（`INT`、`BIGINT`、`VARCHAR`）
* 表要结构清晰、可扩展、易维护
* 高频查询字段要加索引

### 1.3.3 主键（Primary Key）设计

* 唯一标识一条记录
* 查询性能最好（自动建立唯一索引）

### 1.3.4 外键（Foreign Key）设计

* 保证表之间数据关系合法
* 用于一对多、多对一关系
* 可以使用 `ON DELETE CASCADE`、`RESTRICT` 控制删除行为

### 1.3.5 一对多（1: N）表设计

一个 A 对应多个 B，但每个 B 只能对应一个 A。外键放在"多"的那一方。

### 1.3.6 多对多（M: N）表设计

A 可以关联多个 B，B 也能关联多个 A。必须使用"中间表（关系表）"，关系表包含两个外键。

* 学生表（`students`）：存学生信息，例如小明、阿强、小美
* 课程表（`courses`）：存课程信息，例如语文、数学、历史
* 中间表（`enroll`）：只存"谁选了哪门课"

# 3. SQL 的三个组成部分

SQL 是所有关系型数据库通用的标准语言，用于创建结构、管理数据与控制权限。其特点是声明式语言，也就是开发者只需要说明"想要什么结果"，而不需要描述具体执行步骤。SQL 的三个组成部分（DDL、DML、DCL）覆盖了数据库操作的所有核心功能，是学习数据库的基础框架。

## 3.1 DDL（数据定义语言）

DDL（Data Definition Language）用于创建、修改和删除数据库对象，例如数据库本身、表、索引、视图等。

常用操作包括：

* `CREATE`：用于创建数据库或表
* `ALTER`：修改表结构，如添加字段或更改字段类型
* `DROP`：删除表或数据库

DDL 操作会影响数据库的结构，因此需要格外谨慎。在生产环境中，DDL 操作通常需要提前评估，确保不会对现有系统造成影响。

示例：

```sql
CREATE DATABASE school;
```

## 3.2 DML（数据操作语言）

DML（Data Manipulation Language）负责对表中的记录进行增删改查，是开发者最常使用的 SQL 类型。它主要用于业务逻辑层面，例如用户注册（`INSERT`）、用户登录时检索信息（`SELECT`）、修改资料（`UPDATE`）、删除数据（`DELETE`）等。

DML 操作与 DDL 不同，它不会影响表结构，只会影响表内容。此外，在事务环境中，DML 是最常被事务所控制的语句类型，例如"先减库存，再创建订单"必须放在一个事务内。

* `INSERT`
* `SELECT`
* `UPDATE`
* `DELETE`

示例：

```sql
SELECT * FROM students;
```

## 3.3 DCL（权限控制）

DCL（Data Control Language）用于管理数据库的权限系统。例如：

* `GRANT`：授予用户某一数据库或表的访问权限
* `REVOKE`：撤销用户权限
* `CREATE USER`：创建新用户

权限控制是企业级数据库使用的重要环节，例如读写分离、不同部门的数据隔离、生产数据库的访问授权等，都依赖合理的 DCL 配置。

# 5. DDL（建库建表）

## 5.1 创建数据库

```sql
CREATE DATABASE school CHARACTER SET utf8mb4;
```

在创建数据库时，设置字符集是非常重要的一步。`utf8mb4` 是目前 MySQL 推荐使用的字符集，完全兼容 Unicode，可正确存储中文、表情符号、特殊符号等内容。企业中几乎所有新项目都统一采用 `utf8mb4`，以避免后续字符集迁移问题。

## 5.2 使用数据库

```sql
USE school;
```

`USE` 命令用于切换当前操作的数据库，让后续所有 SQL 都作用于该数据库。

## 5.3 创建学生表

```sql
CREATE TABLE students (
    id INT PRIMARY KEY AUTO_INCREMENT,
    name VARCHAR(50) NOT NULL,
    age INT,
    grade VARCHAR(10),
    created_at DATETIME DEFAULT CURRENT_TIMESTAMP
);
```

解释：

* `id`：主键，自增长，确保唯一性
* `name`：非空字段，表示学生姓名
* `age`：整数类型，存储年龄
* `grade`：班级信息
* `created_at`：记录创建时间

MySQL 在执行建表语句时会自动为主键创建索引，提高查询效率。

## 5.4 查看表结构

```sql
DESC students;
```

# 6. DML（增删改查）

## 6.1 插入数据

```sql
INSERT INTO students(name, age, grade)
VALUES ('张三', 18, '高三');
```

`INSERT` 语句用于向表中添加一条新纪录。这里的示例展示了最基本的插入方式：指定字段名称，并为其提供相应的值。

在实际业务中，插入操作常用于：

* 新用户注册
* 新订单创建
* 新文章发布
* 新日志写入

开发者在插入数据时需要确保字段与值一一对应，并遵循表结构的约束条件，如非空字段、默认值等。

## 6.2 查询

```sql
SELECT * FROM students;
SELECT * FROM students WHERE age > 17;
SELECT * FROM students WHERE name LIKE '%张%';
```

`SELECT` 是 SQL 中最重要的语句，用于检索表中已有的数据。

上述示例演示了三种常见查询：


1. 查询全部记录：\n`SELECT * FROM students;`\n用于快速查看整个表的内容。
2. 条件查询：\n`WHERE age > 17`\n常用于过滤满足特定条件的数据，如年龄、状态、类型等。
3. 模糊搜索：\n`LIKE '%张%'`\n常用于按关键字搜索姓名、标题等。

查询语句越复杂，对数据库优化的要求越高，因此良好的查询习惯可以显著提升应用性能。

## 6.3 更新

```sql
UPDATE students SET age = 20 WHERE id = 1;
```

`UPDATE` 用于修改表中已有的数据。更新语句必须谨慎使用，尤其是 `WHERE` 条件。如果遗漏条件，可能导致整张表被修改。

例如：

```sql
UPDATE students SET age = 20;
```

会将所有学生的年龄都改成 20，这在生产环境中可能会引发严重数据事故。因此，更新操作通常需要结合唯一标识，如主键 ID，以确保数据修改是精确的。

## 6.4 删除

```sql
DELETE FROM students WHERE id = 1;
```

`DELETE` 用于删除记录。与更新类似，删除语句必须具备明确的定位条件，避免误删数据。

# 7. 事务（Transaction）

事务（Transaction）是数据库中最重要的机制之一，用于确保数据操作的可靠性。保证多条操作作为一个整体，要么全部成功，要么全部失败，只要业务中包含"多个步骤一起完成"，就必须使用事务。

事务遵循 ACID 原则：

* **A：原子性（Atomicity）**\n多条操作要么全部成功，要么全部失败，不存在部分成功。
* **C：一致性（Consistency）**\n数据必须从一个合法状态转移到另一个合法状态，不能出现破坏规则的情况。
* **I：隔离性（Isolation）**\n多个事务同时运行时不能互相干扰。
* **D：持久性（Durability）**\n事务提交之后数据必须持久存储，不会丢失。

在实际业务中，事务常见于：

* 扣库存并创建订单
* 用户转账
* 修改多个表时需要保持同步
* 删除用户时需要清理关联数据

事务保证复杂操作的可靠执行，是企业级系统的基础保障。

## 7.1 事务的流程

一个事务由三部分构成：

```sql
START TRANSACTION;  -- 开启事务
... 多条 SQL ...
COMMIT;             -- 提交
```

如果执行过程出错：

```sql
ROLLBACK;           -- 回滚到事务之前的状态
```

事务的基本流程包括：


1. `START TRANSACTION`：开启事务
2. 执行多条 SQL 语句
3. `COMMIT`（提交）：全部成功后写入数据库
4. `ROLLBACK`（回滚）：出现错误时取消所有修改

在事务提交前，修改的数据只对当前事务可见，对其他事务不可见，这就是隔离性的体现。

事务使用得是否合理，直接关系到系统的稳定性与正确性。

## 7.2 事务示例

下面用修改学生姓名的例子展示事务的真实行为。

### 7.2.1 开启事务并修改，但不提交

```sql
START TRANSACTION;

UPDATE students
SET name = '张三_未提交'
WHERE id = 1;
```

此时，当前事务已经将名称更新为"张三_未提交"，但因为尚未提交，修改并未真正写入数据库文件。该修改只存在于事务的临时版本中，因此：

* 当前事务可以查看到修改后的值
* 其他客户端仍然看到旧值

这是事务隔离性的典型表现。

#### 当前事务窗口查询：

```sql
SELECT name FROM students WHERE id = 1;
```

结果是：

```
张三_未提交
```

当前事务能看到自己的修改。

在事务内查询数据时，数据库会优先返回当前事务产生的临时数据，而不是数据库中的已提交数据。这种行为保证了当前事务内部的一致性。

这也解释了为什么事务被称为"操作的最小单位"，事务内的所有变化对外不可见。

#### 另外一个客户端查询：

```sql
SELECT name FROM students WHERE id = 1;
```

结果仍然是：

```
张三
```

说明：未提交的数据只能在当前事务里看到，其他用户完全看不到（隔离性）。

### 7.2.2 回滚事务

如果执行：

```sql
ROLLBACK;
```

再查：

```sql
SELECT name FROM students WHERE id = 1;
```

结果恢复成：

```
张三
```

说明：未提交的修改可以被取消，回滚会撤销事务内的所有修改，使数据恢复到事务开始前的状态。这是事务保证一致性与安全性的关键机制。

### 7.2.3 开启事务并提交修改

```sql
START TRANSACTION;

UPDATE students
SET name = '张三_已提交'
WHERE id = 1;

COMMIT;
```

任意客户端查询：

```sql
SELECT name FROM students WHERE id = 1;
```

结果都是：

```
张三_已提交
```

说明：当事务执行 `COMMIT` 后，修改正式写入数据库日志和数据文件，此时所有客户端都能看到最新值，这是持久性（Durability）的体现。

## 7.3 为什么要用事务

事务能保证：

* 操作要么全部成功，要么全部失败
* 避免只更新了一半的数据
* 保证重要业务的正确性

典型场景包括：

* 扣库存
* 转账
* 支付
* 创建订单
* 删除用户及其关联数据

只要业务涉及"多个 SQL 必须一起成功"，就必须使用事务。

# 8. 并发问题：没有隔离会出现什么？

在多用户系统中，多条查询或修改请求往往会同时进行。若数据库没有提供足够的隔离机制，不同事务之间可能互相干扰，产生错误的读写结果。这些错误不仅会导致数据混乱，还可能造成严重的业务逻辑问题。

因此，在学习数据库时，理解并发问题是掌握事务隔离级别和 ACID 原则的关键。这三类问题是数据库理论中的经典现象，也是数据库设计的基础考量。

## 8.1 脏读（Dirty Read）

读到了别人**未提交**的数据。脏读违反了事务隔离性原则，是最不安全的一种读取行为。

**例子**：\n事务 A 把成绩改成 100（没提交）\n事务 B 查询看到是 100\n事务 A 回滚 → B 读到了一个"从未真正存在的数据"

## 8.2 不可重复读（Non-repeatable Read）

同一事务内两次查询同一行结果不一样。这就导致同一事务内，两次查询结果不稳定。

**例子**：\nA 第一次查询成绩为 90\nB 修改成绩为 80 并提交\nA 再查变成 80 → 行记录内容发生变化

## 8.3 幻读（Phantom Read）

同一事务内，两次查询发现多出（或少了）记录。

**例子**：\nA 查询某班有 30 人\nB 插入一个学生\nA 再查变成 31 人 → 查询结果的"行数量"变化了

## 8.4 隔离级别（MySQL 默认 RR）

| 隔离级别 | 脏读  | 不可重复读 | 幻读  |
|------|-----|-------|-----|
| 读未提交 | ✅   | ✅     | ✅   |
| 读已提交 | ❌   | ✅     | ✅   |
| 可重复读（默认） | ❌   | ❌     | ✅\* |
| 串行化  | ❌   | ❌     | ❌   |

MySQL 默认使用 `Repeatable Read`，是因为：

* 它能够避免脏读
* 避免不可重复读
* 在多数情况下避免幻读
* 性能较好
* 与 InnoDB 的 MVCC 机制适配度高

因此默认 RR 是一个面向生产环境的全局最优策略。

理解隔离级别后，开发者可以正确选择需要的数据库行为，以保证系统性能与数据一致性。

# 9. Go 原生操作 MySQL

Go 可以通过 MySQL 驱动直接执行 SQL，这是底层能力。

## 9.1 安装驱动

```bash
go get github.com/go-sql-driver/mysql
```

## 9.2 连接数据库

```go
db, err := sql.Open(
    "mysql",
    "root:123456@tcp(127.0.0.1:3306)/school?charset=utf8mb4&parseTime=True&loc=Local",
)
```

常见参数解释：

* `charset=utf8mb4`：设定字符集
* `parseTime=True`：正确解析时间字段
* `loc=Local`：使用本地时区

建立连接并不会立即访问数据库，只有在第一次执行查询时才会真正建立连接。

## 9.3 插入

```go
db.Exec("INSERT INTO students(name, age) VALUES (?, ?)", "王五", 16)
```

`Exec` 用于执行不返回结果的 SQL，例如 `INSERT`、`UPDATE`、`DELETE`。使用占位符 `?` 预处理，能够防止 SQL 注入，是处理用户输入的标准方式。

### 9.3.1 Go 不会执行 SQL

Go 自身不会处理"插入""查询"这种操作，它只是把 SQL 字符串发送给 MySQL。

这句代码中最核心的部分是：

```go
("INSERT INTO students(name, age) VALUES (?, ?)", "王五", 16)
```

这几乎就是纯 SQL。Go 做的事情只有两件：


1. 把这串 SQL 文本传给 MySQL
2. 等待 MySQL 执行完返回结果

例子：\nSQL 说："插入一个学生。"\nGo 说："好的，我帮你把这条命令送过去。"

所以，在这一行里：

```go
db.Exec("INSERT INTO students(name, age) VALUES('张三', 18)")
```

* `Exec()` 是 Go 的方法
* `"INSERT ..."` 是 SQL 语言
* 负责执行的是数据库（MySQL），不是 Go

**为什么 Go 里写 SQL 仍然是 SQL 语言？**\n因为 SQL 是数据库的语言，Go 不会解释 SQL，MySQL 才是真正执行 SQL 的程序。所以你在 Go、Java、Python、Node.js 里面写 SQL，SQL 的语法永远没变，只是不同语言负责"发送请求"。

SQL 和 Go 之间没有语法关系。SQL 是 SQL，Go 是 Go。Go 只是把 SQL 字符串丢给 MySQL，让它去执行。

## 9.4 更新

```go
db.Exec("UPDATE students SET age=20 WHERE id=1")
```

依旧是 SQL 在做更新，Go 不参与任何"数据库逻辑"。

## 9.5 查询单条

```go
row := db.QueryRow("SELECT name, age FROM students WHERE id = ?", 1)
```

Go 不懂"SELECT"是什么意思，它只会把这一句 SQL 送给 MySQL。

## 9.6 查询多条

```go
rows, _ := db.Query("SELECT id, name FROM students WHERE age > ?", 15)
```

## 9.7 事务

```go
tx, _ := db.Begin()
tx.Exec("UPDATE students SET age = age + 1 WHERE id = 1")
tx.Exec("INSERT INTO score_log(student_id, change_amount) VALUES (1, 1)")
tx.Commit()
```

# 10. GORM（ORM 框架）

GORM 的核心价值在于将数据库表与 Go 的 struct 建立映射关系，让开发者可以使用面向对象的方式处理数据，而无需手动编写 SQL。

它的优势包括：

* 自动生成 SQL，减少重复劳动
* 自动建表、迁移，加快开发效率
* 自动将查询结果填入 struct，避免手动 Scan
* 链式查询使代码更加清晰
* 内置事务简化复杂数据操作
* 高度可定制，支持复杂查询、钩子、关联关系等

在企业级项目中，ORM 是极大提升开发速度的利器，尤其适合快速迭代的业务场景。

## 10.1 为什么需要 GORM？

尽管原生 SQL 灵活、高效，但在日常开发中会面临大量"样板代码"，例如：

* 每个查询都要写 `SELECT` 与字段列表
* 每一行结果都要手动 `Scan`
* 表结构变动后，几十处 SQL 必须逐个同步更新

这些问题在长期维护中会产生大量成本。

而 GORM 通过 struct 和标签自动映射字段，将上述问题大幅简化，使：

* 数据结构统一由 Go struct 决定
* SQL 自动生成，不易出错
* 字段映射自动完成
* 查询语句更简洁易读
* 更适合大型项目的多人协作

这就是 ORM 在现代后端框架中普遍使用的根本原因。

## 10.2 安装 GORM

```bash
go get -u gorm.io/gorm
go get -u gorm.io/driver/mysql
```

GORM 由两部分组成：


1. `gorm.io/gorm`：框架本体
2. `gorm.io/driver/mysql`：数据库驱动

## 10.3 连接数据库（GORM 版本）

```go
db, _ := gorm.Open(mysql.Open(
    "root:123456@tcp(127.0.0.1:3306)/school?charset=utf8mb4&parseTime=True&loc=Local",
), &gorm.Config{})
```

与原生 SQL 相比，GORM 封装了连接池、SQL 执行、事务管理等底层细节，使开发者只需要提供连接字符串即可完成数据库连接。

`gorm.Config{}` 可以接受非常多的配置，例如：

* 是否打印 SQL
* 是否禁止自动创建时间字段
* 是否启用软删除等

这是 GORM 灵活性的一部分。

## 10.4 定义模型（struct 对应一张表）

```go
type Student struct {
    ID        uint      `gorm:"primaryKey"`
    Name      string
    Age       int
    Grade     string
    CreatedAt time.Time
}
```

模型（Model）是 GORM 最核心的概念。

* struct 名称默认映射为复数表名（`Student` → `students`）
* 字段名默认映射为同名列（`Name` → `name`）
* `ID` 自动识别为主键
* `time.Time` 类型会自动生成时间字段

如果想与旧系统兼容，例如一些历史项目表名不是复数形式，就可以通过 `TableName()` 手动指定。

模型定义得越清晰，后续数据操作越方便。

如果要自定义表名：

```go
func (Student) TableName() string {
    return "students"
}
```

## 10.5 自动建表（AutoMigrate）

```go
db.AutoMigrate(&Student{})
```

`AutoMigrate` 是 GORM 的亮点之一：

* 自动创建不存在的表
* 自动添加字段
* 自动同步结构变更

虽然 `AutoMigrate` 很方便，但在某些严格的生产环境（例如金融）中，数据库结构更偏向手工维护以避免误操作。但是在教学、开发、测试环境中，它极大提高效率，是非常推荐的方式。

# 11. GORM 的 CRUD

## 11.1 插入数据（Create）

```go
db.Create(&Student{Name: "张三", Age: 18, Grade: "高三"})
```

`Create` 会自动：

* 生成 `INSERT` 语句
* 填充主键 ID
* 记录创建时间
* 更新结构体中的字段值

无需手写 SQL，是 GORM 提升开发效率的核心功能之一。

## 11.2 查询单条（First / Take / Last）

```go
var stu Student
db.First(&stu, 1) // 根据主键查
```

按条件：

```go
db.First(&stu, "name = ?", "张三")
```

`First` 会按照主键升序查找第一条记录，也可以根据条件查找。

常用方法：

* `First`：有主键排序，最常用
* `Take`：不排序
* `Last`：主键倒序排序

GORM 会自动将数据填充到结构体中，不需要 `Scan`。

## 11.3 查询多条（Find）

```go
var list []Student
db.Where("age > ?", 17).Find(&list)
```

`Find` 会根据条件查询所有匹配的结果，并自动填充到 slice 中。

GORM 的链式语法允许叠加多个条件，使查询语句结构更清晰，代码可读性更强。

## 11.4 更新（Update / Updates）

单字段：

```go
db.Model(&Student{}).Where("id = ?", 1).Update("age", 20)
```

多字段：

```go
db.Model(&Student{}).Where("id = ?", 1).
    Updates(Student{Age: 20, Grade: "高三"})
```

更新方法包括：

* `Update`：更新单个字段
* `Updates`：结构体或 map 多字段更新

GORM 提供了字段选择策略，例如忽略零值字段、强制更新零值字段等，可适应不同业务需求。

## 11.5 删除（Delete）

```go
db.Delete(&Student{}, 1)
```

对应 SQL：

```sql
DELETE FROM students WHERE id = 1;
```

## 11.6 链式查询（GORM 的特色）

可以连续写查询条件：

```go
db.Where("age > ?", 16).
    Where("grade = ?", "高三").
    Order("age desc").
    Limit(10).
    Find(&list)
```

链式查询是 GORM 的重要特性，使查询变得：

* 结构清晰
* 条件可叠加
* 可读性强
* 不易拼写错误

# 12. 事务（GORM 的事务封装）

GORM 的事务非常容易用。

## 12.1 写法 1：自动事务

```go
db.Transaction(func(tx *gorm.DB) error {
    if err := tx.Create(&Student{Name: "A"}).Error; err != nil {
        return err // 自动回滚
    }

    if err := tx.Create(&Student{Name: "B"}).Error; err != nil {
        return err // 自动回滚
    }

    return nil // 自动提交
})
```

自动事务会：

* 自动开启事务
* 执行函数内容
* 若函数返回 `error` → 自动回滚
* 若函数返回 `nil` → 自动提交

该方式最安全、最简洁，也是推荐使用的方式。

## 12.2 写法 2：手动事务

```go
tx := db.Begin()

tx.Create(&Student{Name: "A"})
tx.Model(&Student{}).Where("id=1").Update("age", 20)

tx.Commit() // or tx.Rollback()
```
